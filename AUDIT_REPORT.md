## Appendix A — Order lifecycle as found in code

- **Produced statuses**: `RECEIVED` (on create + on add-items reset), `PREPARING`, `READY`, `SERVED` (via `PATCH /:id/status`), `COMPLETED` (via `POST /:id/close`). `PENDING` never written; `CANCELLED` never written (no endpoint).
- **Allowed transitions** (`orderService.ts:313-327`): RECEIVED→PREPARING (CHEF/MANAGER/ADMIN); PREPARING→READY (CHEF/MANAGER/ADMIN); READY→SERVED (WAITER/MANAGER/ADMIN) + bulk item→SERVED. All else → `ORDER_TRANSITION_NOT_ALLOWED` (403) / conflict → 409. Optimistic-concurrency via `updateMany(where:{status:old})`.
- **Emits per transition**: `order:status_changed {orderId,status}` → `order:<id>` + `kitchen` + `waiters` (close also same three; **not** `admin`/`table:<id>`). Create/add-items → `order:new` → kitchen/waiters(/admin on create only). `callWaiter` → `waiter:called` → waiters (+`table:<id>`). `requestBill` → `bill:requested` → waiters+admin(+`table:<id>`) + table→BILL_REQUESTED. `toggleMenuAvailability` → `menu:availability_changed` → all (no listeners). `notifyLowStock` → `inventory:low_stock` → admin (no listeners). `item:status_changed` never emitted.

## Appendix B — Money trace (sample: 2× Butter Chicken ₹420 + 1× Garlic Naan ₹75 + add-on ₹20×2, 5% GST, coupon FIXED ₹50)

1. Request: quantities/ids only. 2. `calculateOrderTotals`: subtotal=(420×2)+(75)+(20×2)=955.00; tax per-line `round2(line×5%)` summed; discount 0 at create; total=subtotal+tax. 3. DB `Order{subtotal,taxAmount,discount:0,total}` + item snapshots. 4. Preview: `total=subtotal+tax−couponDiscount` (coupon capped at subtotal, 2dp). 5. Close: `tendered==amountDue` exact else 400; writes payments PAID + COMPLETED + frees table + audit. 6. Invoice: recomputes line tax/slabs from snapshots (B-18 drift note) + stored subtotal/discount/total. 7. Reports: aggregate stored `total/taxAmount` of COMPLETED. 8. Razorpay: `due×100` paise ints. Client `Number()` paths flagged B-17; none feed the stored totals.

## Appendix C — Inventory trace

- Order → `deductIngredientsForOrder(items,tx)` inside same `$transaction` → per-ingredient `qtyUsed×quantity` aggregated → guarded `decrement`. No-recipe items deduct nothing (by design). Low-stock = `stockQty<=reorderLevel` (JS filter after fetch) → `inventory:low_stock`→admin after order/add/ingredient/recipe changes. Recipe read/write round-trip exists server-side; UI breaks it (B-01–B-04). No stock restore path (no cancel/void — M-01/M-02).
